Opus Platform API

Internal API for music curation, style class management, and audio enrichment. Deployed on Render, backed by Supabase PostgreSQL.

Architecture

Browser (GitHub Pages)
  └── api-client.js  ──▶  x-api-key header
        └── Fastify API (Render)  ──▶  Supabase (PostgreSQL)

Base URL: https://opus-platform.onrender.com  ·  All routes prefixed /v1  ·  /health requires no auth.

Authentication

⚠️ Every endpoint except /health and the Spotify OAuth callbacks requires the x-api-key header. 
# curl
curl -H "x-api-key: YOUR_KEY" https://opus-platform.onrender.com/v1/styles

# fetch
fetch("/v1/styles", { headers: { "x-api-key": OPUS_CONFIG.API_KEY } })

Errors

{ "error": { "message": "Description", "status": 400 } }
StatusMeaning
400Bad request — malformed body or invalid values
401Unauthorized — missing or wrong API key
409Conflict — record already exists
500Internal server error

Database Schema

Core Tables (existing)

sim_styles — id, name library_songs — id, title, artist, album, peak_year, run_time_seconds, isrc, styles sim_style_songs — style_id, library_song_id, sim_duration_seconds sim_style_song_classes — style_id, library_song_id, class_code (A|B|C|REST), moved_at sim_style_class_weights — style_id, class_code, weight_pct

Added by Opus

opus_curator_schedules — style_id, curator_name, cadence, last_updated, notes opus_style_moods — style_id, mood, position (1–6) playlist_syncs — playlist_id, playlist_name, style_id, last_synced_at, last_sync_added, last_sync_removed, last_sync_unmatched song_attributes — library_song_id, source, bpm, key, mode, energy, danceability, valence, acousticness, instrumentalness, speechiness, loudness, duration_seconds, time_signature, raw (JSONB) UNIQUE(library_song_id, source) opus_acquisition_queue — id, title, artist, isrc, status (want|purchased|in_library), source (itunes|amazon|ilm|serviced), notes, playlist_name, created_at, updated_at
ℹ️ Class codes: Valid values are A B C REST. Stored uppercase. REST = explicitly not played. Uncategorized = in style but no row in sim_style_song_classes.

Styles

GET /v1/styles List all styles

Returns all styles ordered by name.

{ "data": [{ "id": "uuid", "name": "Bubbakoo B" }] }
POST /v1/styles Create a new style 
// Body
{ "name": "New Style Name" }

// Response 201
{ "ok": true, "style": { "id": "uuid", "name": "New Style Name" } }
GET /v1/styles/:styleId/dna Aggregate audio profile

Computes the audio DNA from all enriched songs in a style. Powers the Style DNA card, outlier row highlighting, and Add Songs drawer context hints.

{
  "bpm": { "avg": 112, "std": 14, "min": 75, "max": 190,
           "outlierLow": 91, "outlierHigh": 133 },  // ±1.5 SD
  "energy": 0.72,  "danceability": 0.68,
  "valence": 0.54, "acousticness": 0.18,
  "genres": [{ "genre": "hip-hop", "count": 48, "pct": 52 }],
  "keys": ["C", "F", "G", "A"],
  "majorPct": 64,
  "enrichedCount": 93, "totalCount": 93
}

Returns {} when no enriched songs exist. Outlier thresholds are ±1.5 standard deviations from the BPM mean.

Tracks & Classes

GET /v1/styles/:styleId/tracks All tracks in a style

Returns style membership joined with full song metadata. Capped at 3,000 rows.

{ "data": [{
  "library_song_id": "uuid",
  "sim_duration_seconds": 214,
  "song": { "id", "title", "artist", "album", "peak_year", "run_time_seconds", "styles" }
}] }
GET /v1/styles/:styleId/assignments Class assignments for a style 
{ "data": [{ "library_song_id": "uuid", "class_code": "A", "moved_at": "2026-02-20T18:00:00Z" }] }
PUT /v1/styles/:styleId/assignments Bulk upsert assignments

Conflict target: (style_id, library_song_id). Class codes normalized to uppercase. Valid: A B C REST.

{ "assignments": [{ "library_song_id": "uuid", "class_code": "A" }] }
DELETE /v1/styles/:styleId/assignments Remove assignments → Uncategorized 
{ "songIds": ["uuid1", "uuid2"] }
GET /v1/styles/:styleId/weights Class weight distribution 
{ "data": [
  { "class_code": "A", "weight_pct": 35 },
  { "class_code": "B", "weight_pct": 35 },
  { "class_code": "C", "weight_pct": 30 }
] }
PUT /v1/styles/:styleId/weights Update weights (must sum to 100) 
{ "weights": [
  { "class_code": "A", "weight_pct": 50 },
  { "class_code": "B", "weight_pct": 30 },
  { "class_code": "C", "weight_pct": 20 }
] }
// Response: { "ok": true, "upserted": 4 }
GET /v1/styles/:styleId/playback-profile Full composite playback payload

Integration-ready payload for the playback engine. Append ?include_track_ids=true for debug output.

{
  "data": {
    "style_id": "uuid",
    "mode": "CLASS_WEIGHTED",  // or "LEGACY"
    "weights": { "A": 50, "B": 30, "C": 20 },
    "pools": {
      "A": { "count": 120 }, "B": { "count": 80 },
      "C": { "count": 40  }, "UNCATEGORIZED": { "count": 12 },
      "REST": { "count": 7 }
    }
  }
}

LEGACY when no A/B/C tracks are assigned or weights sum to 0. CLASS_WEIGHTED otherwise.

Songs & Audio Attributes

GET /v1/songs/search?q=&limit=20 Fuzzy search by title + artist

Splits query into tokens — each token must appear in title or artist. So "petty learning" matches Tom Petty's "Learning to Fly". Max 50 results. Audio attributes included inline when available (prefers soundcharts source).

{ "data": [{
  "id": "uuid", "title": "Learning to Fly", "artist": "Tom Petty",
  "album": "Into the Great Wide Open", "peak_year": 1991,
  "bpm": 138, "energy": 0.61, "key": "5", "mode": "major",
  "danceability": 0.48, "valence": 0.72
}] }

Attribute fields are null when the song hasn't been enriched.

POST /v1/styles/:styleId/songs Add a song to a style

Inserts into sim_style_songs with no class assignment — lands as Uncategorized. Returns 409 if already in the style.

// Body
{ "library_song_id": "uuid" }

// Response 201
{ "ok": true, "song": { "id", "title", "artist", ... } }
GET /v1/songs/attributes?ids=uuid1,uuid2 Batch fetch audio attributes

Returns full song_attributes rows including raw JSONB for the given library_song_id list. Always returns the soundcharts source row. Used by track metadata modal and outlier detection.

[{
  "library_song_id": "uuid", "source": "soundcharts",
  "bpm": 112, "key": "0", "mode": "major",
  "energy": 0.72, "danceability": 0.65, "valence": 0.54,
  "acousticness": 0.12, "instrumentalness": 0.0,
  "speechiness": 0.04, "loudness": -5.2, "time_signature": 4,
  "raw": { /* full Soundcharts response: genres, labels, composers, etc. */ }
}]
GET /v1/songs/enriched?limit=1000&offset=0 All enriched songs, paginated

Returns all library songs with audio attributes joined with title/artist. Used by the Style Builder to load the full enriched library client-side. Genres are extracted from raw JSONB. Max 2,000 per page.

{
  "data": [{
    "library_song_id": "uuid", "title": "Song Title", "artist": "Artist",
    "bpm": 112, "energy": 0.72, "danceability": 0.65,
    "valence": 0.54, "acousticness": 0.12,
    "key": "0", "mode": "major",
    "genres": ["hip-hop", "r&b"]
  }],
  "total": 1000, "offset": 0, "limit": 1000
}
GET /v1/songs/enriched/count Total enriched song count

Returns the total number of songs with audio attributes. Used by the Style Builder to calculate accurate load progress before paginating through /songs/enriched.

{ "count": 93 }
POST /v1/songs/enrich Enrich songs via Soundcharts

Fetches audio attributes for unenriched songs via a 2-step Soundcharts lookup: ISRC → UUID → full metadata. Processes up to limit songs with a 200ms delay between requests to respect rate limits.

// Body (all optional)
{
  "limit": 100,            // max 200, default 100
  "offset": 0,
  "style_name": "Bubbakoo B"  // scope to a specific style
}

// Response
{ "ok": true, "total": 93, "enriched": 87, "failed": 6, "results": [...] }
⚠️ Requires SOUNDCHARTS_APP_ID and SOUNDCHARTS_API_KEY env vars. Only songs with an ISRC can be enriched (~94.5% of the library, ~115k songs).

Curator Schedules

Cadence values and their intervals: weekly (7d) · biweekly (14d) · monthly (30d) · quarterly (90d)

GET /v1/curator-schedules List schedules

Optional query params: ?curator_name= and ?style_id=. Also: GET /v1/curator-schedules/curators for a distinct list of curator names.

PUT /v1/curator-schedules Upsert a schedule 
{ "style_id": "uuid", "curator_name": "Maya Chen",
  "cadence": "monthly", "last_updated": "2026-03-01",
  "notes": "Focus on new releases" }  // notes optional
PATCH /v1/curator-schedules/:styleId/mark-updated Stamp last_updated = today

No body required. Sets last_updated to today's date on the schedule for the given style.

DELETE /v1/curator-schedules/:styleId Remove a schedule

No body required.

Mood Tagging

Each style can have up to 6 moods. Position is significant — Mood 1 is primary. Valid values:

Calm Classic Comfortable Current Energetic Festive Fun Intimate Joyful Modern Peaceful Premium Professional Reflective Relaxed Sophisticated Soulful Upbeat Uplifting Vibrant Warm Welcoming

GET /v1/styles/:styleId/moods Ordered moods for a style 
{ "moods": ["Calm", "Relaxed", "Warm"] }
GET /v1/moods/all All styles with moods (bulk)

Used for bulk loading on the Mood Tagging page. Returns all styles that have at least one mood assigned.

PUT /v1/styles/:styleId/moods Full replace moods (ordered, max 6)

Full replace — send the complete ordered array. Index 0 = Mood 1 = primary.

{ "moods": ["Calm", "Relaxed", "Peaceful"] }
DELETE /v1/styles/:styleId/moods Clear all moods for a style

No body required.

Spotify Sync

Playlists sync nightly at 3am UTC via GitHub Actions (.github/workflows/nightly-sync.yml). Tracks are matched using a 4-tier strategy: Spotify ID → normalized title/artist → aggressive normalization → fuzzy feat/remix variants.

POST /v1/spotify/register-sync Link a playlist to a style

Safe to call again on an existing playlist (upserts).

{ "playlist_url": "https://open.spotify.com/playlist/...", "style_id": "uuid" }
POST /v1/spotify/run-sync Run sync now

Omit playlist_id to run all registered syncs.

// Body
{ "playlist_id": "spotify_id" }  // optional — omit to run all

// Response
{ "results": [{
  "ok": true, "playlist_id": "...",
  "added": 5, "removed": 2, "unmatched": 3, "total_tracks": 87,
  "unmatched_tracks": [{ "spotify": { "title": "...", "artist": "..." } }]
}] }
GET /v1/spotify/syncs List registered syncs

Returns all registered playlist → style sync relationships with last sync stats.

DELETE /v1/spotify/syncs/:playlistId Remove a registered sync

Does not affect songs already added to the style.

Acquisition Queue

Songs flagged for purchase from Spotchecker sessions. Added via the 🛒 Want button on unmatched rows. Persisted in Supabase so the whole team can see what's in the pipeline.

GET /v1/acquisition List acquisition queue

Returns all items ordered by newest first. Optional ?status=want|purchased|in_library filter.

{ "data": [{
  "id": "uuid", "title": "Rich Girl", "artist": "Hall and Oates",
  "isrc": "USRC17607760", "status": "want",
  "source": "itunes", "notes": "For Bubbakoo",
  "playlist_name": "Adult Contemporary",
  "created_at": "2026-03-20T10:00:00Z"
}] }
POST /v1/acquisition Flag a song for acquisition

Returns 409 if the same title+artist is already in want or purchased status.

// Body
{ "title": "Rich Girl", "artist": "Hall and Oates",
  "isrc": "USRC17607760",         // optional
  "playlist_name": "Adult Contemporary",  // optional
  "source": "itunes",             // optional
  "notes": "For Bubbakoo" }       // optional

// Response 201
{ "ok": true, "item": { "id": "uuid", "status": "want", ... } }
PATCH /v1/acquisition/:id Update status, source, or notes

Send only the fields you want to update. Valid statuses: want purchased in_library. Valid sources: itunes amazon ilm serviced.

{ "status": "purchased", "source": "itunes", "notes": "Bought 2026-03-20" }
DELETE /v1/acquisition/:id Remove from queue

No body required.

Adding a New Route

// 1. src/routes/myRoute.js
import { supabase, assertNoError } from '../supabase.js';

export default async function routes(app) {
  app.get('/my-endpoint', async (req, reply) => {
    const { data, error } = await supabase.from('my_table').select('*');
    assertNoError(error, 'Failed to fetch');
    return reply.send({ data });
  });
}

// 2. Register in server.js
import myRoutes from './src/routes/myRoute.js';
await app.register(myRoutes, { prefix: '/v1' });

// 3. Add to api-client.js
OpusAPIClient.prototype.myMethod = async function() {
  const { data } = await this.request('/my-endpoint');
  return data;
};
